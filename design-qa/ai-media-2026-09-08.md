# 图片与视频附件回归（2026-09-08）

本记录只证明新增附件链路的本地真实解码、持久化和协议传输；模拟模型的文字不是实际视觉识别准确性验收。真实服务商测试由主任务单独记录。

## 已实现

- 对话加号提供上传图片、上传视频；支持粘贴图片。文档解析原逻辑保留。
- 图片支持 PNG/JPEG/WebP，输入最大 12 MB、2400 万像素、单边 8192；在本机压缩为 JPEG，单边最多 1024、单帧最多 160 KiB。不会上传原始文件路径或 EXIF。
- 视频支持当前设备可解码的 MP4/WebM/MOV/M4V，最大 50 MB、2 分钟；按时长抽取 1–4 个静态画面，保留采样时间。明确不含音频，不声称逐帧完整观看。原视频不离开本机。
- 每次请求逻辑附件最多 5 份，展开后的文档和视觉帧合计最多 5 份；超限拒绝，不默默删除旧附件。历史图片仍可用于后续追问。
- 媒体模块按需加载，顺序解码，45 秒总超时；取消、换对话、卸载均触发取消及 blob/视频资源释放。PDF 取消会停止后续页面并销毁 worker。
- 压缩帧只保存在当前认证成员的云端工作台，随草稿/消息重载；服务端严格检查类型、实际图片格式、大小、尺寸、时间点和未知字段。
- 修正浏览器视频第 0 秒的空白帧：所有采样均先明确 seek，首帧采样 0.001 秒（界面保留两位小数）。
- 搜索回复的新用量字段 `searchCalls`、`tokenUsageEstimated` 通过合法范围校验后可持久化，不再触发保存 400。

## 保存容量边界

工作台快照现有总上限为 2 MiB，未扩大也不自动清理旧数据。新增附件及实际发送之前预留 1 MiB，供一条最大长度文本回复及来源元数据使用。超过可用保存空间时，拒绝本次添加/发送并保留草稿和旧记录，不调用模型、不扣本次额度。该保守策略也会阻止已有纯文本资料超过 1 MiB 的工作台继续发送，需用户先导出并整理历史；不是 Token 额度耗尽。

容量拒绝以专用 `WorkspaceCapacityError` 识别，显示常驻、可关闭提示，直接提供“导出当前内容”。不会伪装成同步失败；下一次附件或发送容量校验通过后清除提示。导出的 JSON 包含当前草稿和原记录，清理须由用户主动执行。

## 证据与运行

`npx tsx scripts/verify-ai-media.mts` 启动自己的临时 loopback API 与 5176 Vite，创建专属临时成员，所有外网请求被阻断；模型 transport 为明确标注的模拟响应，不使用真实密钥/账号。不会重启或改动用户的 5174 预览或线上服务。

浏览器检查：图片选择和缩略图、草稿保存确认后重载、发送实际 `input_image`、消息附件重载、追问仍附视觉输入、4 秒视频的两个正确采样画面及时间戳、取消不调用上游、三次模拟回复实际本地账本仅结算 450 Tokens，预留归零。
