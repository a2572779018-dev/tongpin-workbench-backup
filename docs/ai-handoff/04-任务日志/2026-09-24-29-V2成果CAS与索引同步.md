# 工作包 29：V2 成果逐条 CAS 与图片索引同步

2026-09-24（Asia/Hong_Kong）。基线 `3b96873`。仅改 AI 专属内部存储、测试及交接；未改“我的任务”“客户脉络图”、WorkBuddy、公开路由或客户端。

## 实际修改

- 内部 `mutateActive` 在草稿/视频草稿参数之外，允许**无新增图片关联**的成果 `put` 创建或更新，使用同一 epoch、实体 revision、mutation ID 回执与事务回滚。客户端可编辑的成果数据不能证明图片最初由该对话生成，因此新增或替换图片 asset ID 暂时拒绝；旧图片关联仅允许保留或移除。成果删除或跨对话/项目搬迁也未开放。
- 写入前复用 V1 成果字段校验，按当前租户/成员同批读取实际对话、可选项目和旧成果；事务内复核父实体版本、成果 CAS、当前账号成果数量上限。对更新成果先清理其旧图片候选，再检查同对话同素材是否被其他成果占用、账号索引行数上限，最后连同成果分块与回执一同提交。索引不是授权；读取仍按工作包 28 校验助手消息、会话/项目、账号图片和指纹。
- V2 meta 新增可加列的 `image_index_version`。旧准备区默认为 0，不能把未重建的图片索引当作已迁移；显式重新准备后才标记 1。真实成员仍是 V1，没有自动迁移/激活。

## 验收和边界

- 人工激活的本地 V2：旧图片关联保留时仍可读，移除后索引随事务失效；新增/替换图片 ID 被拒绝。同 mutation ID 精确重试返回原回执，即使随后成果内容已有变化。重复映射、成果 owner/父实体变化、成果删除、旧索引版本、成果超 500 条、写入中断均拒绝或回滚；同 ID 不同租户独立。真实视频参考读取端对**原有有效映射**通过，拒绝时不调用付费服务商。
- 定向 `workspaceV2Store.test.ts` 与 `generatedAssetReference.test.ts` 共 47/47；全仓 `npm test` 195 文件 1939/1939；bundled workerd + SQLite DO 17/17；双类型检查、Web/API 构建及 `git diff --check` 通过。测试包含非图片成果创建、父对话后续变化仍可重放原回执；使用本地 SQLite 与假视频服务商，未产生付费调用。
- 只实现内部成果 `put` 的受限子集，**没有公开 V2 HTTP 路由、客户端协议或真实账号切换**。图片原始生成来源还需服务端不可伪造的关联记录；此前 V1 中已有的图片关联也不能由本包倒证来源。会话/项目/manifest/附件写入、全账号消息 ID 与数量约束、跨批加载一致性、旧端隔离、Cloudflare V2 单实体请求体上限和实际超过 8 MiB 的端到端发送仍待做。#27 的用户空间故障未解决，不可发布。
