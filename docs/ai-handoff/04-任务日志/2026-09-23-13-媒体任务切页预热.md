# 工作包 13：媒体任务切页预热与登录隔离

开工：2026-09-23（Asia/Hong_Kong）。任务映射：原 #6/#16，解决真实聊天中已完成媒体任务卡片在切页、重进同频 AI 后每次闪现“正在查询原任务”的问题。

边界：只改同频 AI 媒体卡片与内存缓存，以及鉴权模块中清理该缓存的最小调用。沿用已存在的同登录令牌轮换作用域转移；新登录、登出、账号或租户变化必须丢弃私有缓存。缓存不是权限凭据，卡片挂载后仍向服务端 GET 复核；401/403/404 或响应身份不匹配须撤下旧结果。绝不重新 POST 生成或触发扣费。

验收：先用失败测试覆盖终态预热、进行中不缓存、过期、同账号不同登录/租户隔离、登出清理，再实现、运行定向测试与双端类型检查。若视频字节已过内存限额、缓存过期或应用重启，重新读取是必要行为，不把它伪装成“永不加载”。本工作包不用真实模型、视频商和生产数据，不部署、不推送。

## 结果

2026-09-23 17:22（Asia/Hong_Kong）：先确认当前 `AiVideoReply` 对同登录视频字节/播放器已有内存缓存；真正重复闪现的入口是 `MediaTaskReply` 挂载时总将任务视图初始化为空。先写缓存单测并取得缺模块红测，再实现 AI-only `MediaTaskSnapshotCache`，只保留从服务端核验过的 `completed/failed/cancelled` 终态，10 分钟上限、200 条 LRU；进行中、待确认和 `unknown` 永远从 GET 获取。缓存键含独立登录作用域、请求 ID 和图片/视频意图，取用时再核验账号、会话、运行 ID 与意图。

真实聊天卡片挂载时可直接呈现同登录的终态快照，随后仍 GET 原任务复核，绝不重新 POST；服务端返回 401/403/404/409 或任务身份不匹配时立即撤下快照，临时网络失败则保留已核验快照并显示错误。鉴权的原同登录 token 轮换作用域转移保持不变，新登录、登出、换账号或租户时同时清空视频缓存与任务快照。视频/图片本体仍遵循原私有内存缓存与服务端读取，不写本地磁盘。

验证：`MediaTaskReply.test.ts` 的组件服务端渲染验证同登录完成/失败卡片切回无查询占位，新登录/进行中仍查询；缓存测试覆盖过期、LRU、跨租户与同账号新登录隔离、轮换、硬拒绝清理；`npx vitest run` 六个相关测试文件 33/33 通过；`npm run typecheck`、`npm run typecheck:cloudflare`、`npm run build:web`、`git diff --check` 通过。**没有**用真实服务商、旧 Windows 客户端或受限权限账号做端到端复验，因此原 #6/#16 只能标为局部修复待全链验收，不能作为发布通过。
