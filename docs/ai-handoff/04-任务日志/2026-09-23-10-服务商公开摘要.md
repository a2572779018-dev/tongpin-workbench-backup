# 工作包 10：服务商公开摘要的受控接入

2026-09-23（Asia/Hong_Kong）。延续现有同频 AI 主链路；本里程碑不涉及生产部署、付费模型调用、“我的任务”“客户脉络图”或 WorkBuddy 手机预览。

## 问题与边界

此前 Responses 流解析器虽然认识 `response.reasoning_summary_text.delta`，向服务商发出的请求却只有 `reasoning.effort`，未请求官方公开摘要。回答正文里的 `<analysis_summary>` 属于**模型另写的公开说明**，不是服务商提供的真实推理摘要；任何私有思维链、`reasoning_text`、`reasoning_content` 均不得展示。

按 [OpenAI 官方推理指南](https://developers.openai.com/api/docs/guides/reasoning) 与 [Responses 流事件规范](https://platform.openai.com/docs/api-reference/responses-streaming/response/reasoning_summary_part?lang=javascript)：官方 Responses 可通过 `reasoning.summary: "auto"` 请求公开摘要，流中有专门的 `response.reasoning_summary_text.delta`；原始 reasoning tokens 不向应用开放，不能声称拿到完整思维链。

## 本次实现

- 仅 exact `https://api.openai.com`、Responses、已查证模型 `gpt-6-astra` / `o4-mini`、深度或 Pro 文本回答且已设置 `reasoningEffort` 时，在既有 `reasoning` 结构中加入 `summary: "auto"`。B.AI 和其他兼容网关不添该参数，避免 HTTP 400 或模型兼容故障。
- 官方摘要模式不再要求模型在正文另写 `<analysis_summary>`，防止同一回答出现两套来源不明的“思考”；现有其他服务商的简短公开说明保留，但仍不标为真实推理。
- 已由服务商专门的公开摘要 SSE 事件返回时，以经过长度/控制字符/标签校验的服务商摘要作为最终 `analysisSummary`；不会把 `response.reasoning_text.delta`、完整 CoT 或私有标记写入事件/回复。前端仍统一称“分析摘要”。
- 对只在官方终态 `reasoning.summary[].summary_text` 返回公开摘要、没有对应 delta 的情况也做了受控兜底；仅在本次实际请求了官方 `summary:auto` 时读取这个字段，`reasoning.content[].reasoning_text` 与加密推理均不读取。
- 服务商摘要与正文模型自写摘要分开限长：前者最多 2000 字符；超出、包含隐藏标签或格式不符时不推广为最终摘要。完整流仍由原有有界读取器处理。

- `npm run typecheck` 与 `npm run typecheck:cloudflare` 均通过。
- **未做真实服务商验收**：没有调用 OpenAI、B.AI 或任何付费接口。当前用户实际配置的中转商是否产生官方公开摘要仍未知；如果其不提供该事件，界面不可声称显示实时思考。原 33 项中的“真实思考过程/工具调用可视化”仍不能仅凭此局部变更判为完成。
