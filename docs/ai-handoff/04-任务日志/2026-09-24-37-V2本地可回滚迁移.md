# 工作包 37：V2 本地测试账号可回滚迁移

2026-09-24（Asia/Hong_Kong）。仅开发机 SQLite 中 `local-test` 租户的 `local-v2-test-*` 测试账号；没有真实成员激活、生产路由、Cloudflare 部署、付费调用、Mac 替换或 Windows 推送。

## 实际修改

- 增加**默认关闭**的本地迁移入口：构造仓库时须显式开启测试标志，租户和账号名还必须同时满足本地测试约束。正式 Node/Worker 构造均未设置该标志，也没有迁移 HTTP 接口。
- 激活前读取同一 SQLite 快照，逐实体验证分块长度、SHA-256、UTF-8、结构和单实体归属；重建 V1 状态并比对准备时的 source hash、revision、epoch、preparedAt 与原始 V1 内容。消息归属、图片成果、项目/会话目录索引也须与实体一致。最后在事务内复核快照，原子设置 `activated_at` 与 V1 版本闸门。旧客户端对 V1 整账号读取/写入均被拒绝。
- 回滚先从**最新 V2** 实体重建并校验 V1 快照，而不是丢弃 V2 期间的新消息。低于旧 8 MiB 账号上限时，在一个事务内写新 V1 修订和分块、清除本地 V2 实体/激活标记但保留递增 epoch；旧窗口持有的原 revision、旧 V2 窗口持有的 epoch 均不能在再次激活后覆盖新状态。若当前 V2 内容不满足 V1 上限，则拒绝回滚并维持 V2，不能截断用户数据。

## 红绿与验收

- 红测先运行：3 项因正式激活/回滚接口不存在而失败；实现后本地迁移定向 10/10 通过。
- 覆盖默认禁用及非测试账号拒绝、激活→V2 追加→保留新消息回滚、V2 新建会话/草稿回滚、准备快照过期或分块损坏不激活、模拟激活/回滚中途 SQL 失败不留半写入、空字符串激活标记拒绝、回滚后旧 revision/epoch 冲突。复核时还发现旧 V1 未设视频草稿标志时可写 V2 参数使回滚无法重建，已改为拒绝该写入并回归。
- 全仓最终复跑 `npm run build`：198 文件、1994/1994，Web/API 构建与 Web 类型检查通过；`npm run typecheck:cloudflare` 通过；bundled workerd/SQLite DO 17/17。首次全仓曾在既有 Node 登录测试遇偶发 404，该测试单独 53/53 和最终全仓复跑通过；没有把偶发问题认定为已修复。不将本地回归写作生产通过。

## 边界

这只证明开发机**本地测试账号**的可逆迁移，不等于已迁移真实成员。超过旧 8 MiB 后回滚 V1 必须拒绝；工作包 38 将对此、真实 V2 超限主链、多窗口与 Worker 重启做独立验收。#27 仍不能关闭。
