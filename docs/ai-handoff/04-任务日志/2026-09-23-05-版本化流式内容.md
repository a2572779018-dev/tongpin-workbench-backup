# 工作包 05：版本化流式正文与可恢复块边界

开工：2026-09-23（Asia/Hong_Kong）。基线：`codex/ai-continuation-20260923` @ `e723243`，工作树干净。目标：沿用现有生产聊天 `answer_delta` / `run_finished` 事件类型，增加可恢复、可核验的协议版本与 Markdown 块边界；不新建旧版客户端无法识别的事件类型，不改变账本结算或工作区消息存储格式。

允许修改：`shared/ai*` 的浏览器安全协议、LibreChat 派生分块模块、`server/ai/storage.ts` 与 `server/ai/service.ts` 的 AI 事件/回复投影、`src/lib/aiRunStream.ts` 的向后兼容校验及相应定向测试、第三方声明和本交接库。保护：我的任务、客户脉络图、WorkBuddy 手机预览、共享入口及生产部署一律不动。

风险与回滚：已安装 0.1.48 客户端只识别现有事件类型，所以新元数据必须可选且由旧解码器忽略；主 `content` 字符串仍是权威正文，块描述只是按精确源码偏移计算的冗余投影。回滚本工作包提交即可，不能删除历史聊天或用量。测试先证实旧解码、重复事件/断线重放、租户隔离、部分回复与单次扣费，再作构建检查。

## 结果

- 先红：新增服务端 `chatRecovery` 和浏览器 `aiRunStream` 测试后，3 个断言如预期失败（缺 `richContent`、错误块未拒绝、错误事件 ID 未拒绝）。
- 真实 AI 主链：LibreChat 派生 GFM 分块器抽到 `shared/librechatMarkdownBlocks.ts`，同时供 `ChatMessageRow → MarkdownReply` 和 `AiService.settle` 使用。服务端只对**最终已净化、已结算**的 `content` 计算 v1 UTF-16 源码区间；`content` 仍是唯一权威正文，工作区 `schemaVersion:1` 未改，旧消息可继续用旧格式打开。
- SSE 沿用 `run_started / answer_delta / usage_updated / run_finished / run_failed`，仅为现有事件加可选 `schemaVersion:1`、`eventId=requestId:seq`、`attemptId`、`conversationId`。已安装 0.1.48 的解码器忽略新增字段；新版校验其组合和终态内容块偏移。事件仍由原 SQLite 日志保存/分页重放，没有第二次 POST 或重复结算。工具/分派原始增量不得冒充最终展示正文；rich 描述从 settle 后投影生成。
- 初测真实 workerd 启动因 `decode-named-character-reference` 的 DOM `document` 入口失败；定位为测试 esbuild `platform:browser` 误选 browser 条件。AI 和 Dify 两个 workerd 测试 harness 显式 `conditions:["workerd"]`，不修改生产打包配置；之后真 workerd 测试通过。另用隔离的 `wrangler dev --local` 启动当前源码，`127.0.0.1:8787/api/health` 返回 SQLite DO/200，自己关闭进程后端口无监听，未运行会改账号的整站脚本。
- 定向 `cloudflare/src/ai/runtime.workerd.test.ts`、`difyCallback.workerd.test.ts`、`server/ai/chatRecovery.test.ts`、`src/lib/aiRunStream.test.ts`：44/44 通过；另补旧请求缺 `conversationId` 的 v1 服务端回退兼容测 13/13。全仓 `npm test` 第一次 1796/1796 通过；加最后一项测试后首次全量 1796/1797，唯一失败是**未改动的** `server/ai/toolRoutes.test.ts:151` 保存成员工作区偶发 404。该文件单独 13/13 通过，再跑全仓 185 文件、1797/1797 通过；目前只记录为待复现的并发/夹具不稳定，不冒称确定无瑕。`npm run typecheck`、`npm run typecheck:cloudflare`、`npm run build:web`、`npm run build:api`、`npm run cloudflare:check` 均通过。Cloudflare 仅 dry-run，没有部署。
