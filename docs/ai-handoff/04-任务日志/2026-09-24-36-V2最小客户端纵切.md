# 工作包 36：V2 最小客户端纵切

2026-09-24（Asia/Hong_Kong）。在工作包 35 的内部追加事务之上，仅接 #27 所需的成员聊天路径；没有激活真实账号、修改 Cloudflare 生产、付费实测、替换 Mac 或推 Windows。

## 实际接入

- Node API 与 Cloudflare Worker/SQLite DO 共用窄协议：V1 账号 `/bootstrap` 只返回版本号；已激活 V2 才返回目录和 manifest。消息按对话分页；上下文单独读取草稿、附件和所属项目；成果按当前账号、对话、助手消息三重关联读取。旧 V1 `/api/ai/workspace` 不在 V2 客户端路径中。
- 用户端 `TongpinAIPage` 在权限和人设完成后探测版本，V2 渲染独立聊天纵切：新建/重命名对话、用户消息先追加、原 requestId 调用真实流式 AI、从服务端请求账本保存 AI 回复、切会话、重开后分页读取并继续聊天。后台续跑扫描遇 V2 不再读取整份 V1；不同会话的忙状态分离。
- 草稿与附件采用单实体 CAS；网络回执不确定时重放相同 mutationId，并尝试以服务端状态对账，冲突不静默覆盖。发送开始前锁住本会话编辑，避免草稿保存等待期间的新输入被清空。追加用户消息不确定时以同一 mutationId 重试和读回核对；双重网络失败暂停本会话再次发送，避免新请求重复提交。
- 历史上传/项目资料沿用有界附件选择。已有图片/视频成果只有在当前会话授权读取实际媒体画面后才送入后续模型请求，未提供的音频/画面不声称已看到。成果读取失败有可重试卡片。V2 新图片/视频/PPT 生成工具仍未开放，不能绕回 V1 整账号写入；不是“全 AI 功能已经 V2 化”。
- AI 回复提交不信任客户端自报正文/用量/模型，从同租户同账号已完成请求账本重建，并要求当前会话中确有同 requestId 的用户提问。
