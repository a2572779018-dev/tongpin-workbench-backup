## 实际修改

- 审核下一步草稿附件写入时发现：现有客户端在附件为空时省略 `draftAttachments`，V2 准备出的 manifest 因而带 `hasDraftAttachments=false`。直接新增附件实体会得到“已保存但列表不可见”的坏状态，因此先补受限 manifest CAS。
- 只允许 `manifest/root` 的 `hasDraftAttachments` 从 `false` 改为 `true`，原 `base` 的 JSON 语义内容和 `hasVideoDraftSettings` 必须保持相同；其他偏好、活动会话/项目、删除和与其他实体同批写入均拒绝。继承账号/租户、准备 epoch、root revision、mutation ID 精确回执与事务回滚；原 V1 快照不变。
- 限制 manifest 至 128 KiB、嵌套深度至 12 层；独立复核发现并发同 ID 请求可能在预检读写之间误报冲突，已加写前及预检失败后的精确回执复查，并用可控并发夹具覆盖 manifest 与成果写入。
- 这是内部“开启附件容器”前置能力，不是完整 manifest 编辑器；尚未添加 `draftAttachment` 写入，也没有用户端附件功能变更。
