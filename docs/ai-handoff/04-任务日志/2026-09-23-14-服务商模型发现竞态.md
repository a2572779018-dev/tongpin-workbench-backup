# 工作包 14：服务商模型发现竞态

2026-09-23（Asia/Hong_Kong）。只处理同频 AI 管理的模型发现状态，不改生产接入、密钥、成员额度、受保护页面或 WorkBuddy 手机预览。

## 已观察到的风险

- 「服务与模型」按服务商 ID 保存异步 `/models` 结果；编辑 URL / Key 会清空列表并增加请求版本，但管理配置重载等生命周期仍需防止旧请求回填。
- 旧版兼容连接会把已保存密钥查到的模型与草稿发现结果合并；当同一个 URL 更换草稿 Key 时，原 Key 的模型仍可进入下拉列表。旧版聊天/图片的异步测试结果也没有统一的版本校验。
- `/models` 并不等于生成能力或权限；没有可用列表时不得展示本地臆造模型 ID。

## 本工作包

以不访问真实服务商的延迟 Promise 复现旧响应覆盖新凭据，并把连接变更、重载与结果接收绑定到同一轮次。旧版聊天草稿换 Key 后不混入已保存 Key 的模型；旧版图片填写独立 Key/URL 时也不借用聊天模型。保留草稿已选档位、已保存服务与额度；空列表仍明确提示未获可选模型。

本地 `modelDiscoveryRevision.test.ts` 5/5 通过（含并发请求、URL/Key 更换及独立图片凭据），`npm run typecheck` 和 `npm run typecheck:cloudflare` 通过。未对真实服务商发送请求，未验证其 `/models` 兼容性，未部署。对于不提供 `/models` 的服务商，四档位 Harness 仍要求已验证的模型列表，故 #22 不能因此判定全部完成。
