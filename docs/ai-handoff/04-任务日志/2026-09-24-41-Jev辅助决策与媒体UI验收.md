## WorkBuddy 自身说明（非 Jev 推导）

我核对了正式代码，确认 Jev 的 `proceedable` 判断成立：

- 客户端 `mediaAttachments.ts` 的 `compressedFrame()` 用 canvas `toBlob("image/jpeg", 0.78)` 把任何图片/视频帧统一转成 JPEG；`generatedVideoReference.ts` 在转换后校验 `dataUrl.startsWith("data:image/jpeg;base64,")`，转不出来会**正确报错**"原图片无法转换成视频参考图"。
- 因此视频带参考图是**完备的正式链路**；我之前在 API 层直接 POST PNG 被拒（`AI_VIDEO_IMAGE_INVALID`），是**跳过了客户端的 JPEG 转换**，不是产品缺陷。
- 结论：视频带参考图与 PPT 导出**无需改产品代码**，只需在真实 UI 里端到端点一遍验证；这正是 `video_ui` / `ppt_ui` 下一步。

### ② 视频带参考图：通过（参考素材逐字节核对一致）

完整证据链（全部正式代码，仅供应商边界模拟）：

1. 生成图片（真实 512×512 PNG，显示在对话里，带下载/删除）。
2. `POST /api/ai/video-references/generated-asset` → `200`（返回该 asset 的 base64 + sourceFingerprint）。
3. **客户端 canvas 转 JPEG**（`compressedFrame` → `toBlob("image/jpeg",0.78)`）→ `POST /api/ai/video-references` → `200`，reference id `a11a57aa…`。
