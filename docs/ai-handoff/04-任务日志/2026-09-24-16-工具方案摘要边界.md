# 工作包 16：工具方案展示摘要不阻断有效任务

2026-09-24（Asia/Hong_Kong）。基线 `24b702b`，工作树干净；仅主任务写入。范围限 AI 专属 `server/ai/capabilities.ts`、对应测试和交接记录，不修改“我的任务”“客户脉络图”、共享入口或 WorkBuddy 预览。

## 目标与证据起点

原 #2/#4/#32 需要一次对话完成工具任务。只读审计发现 `parseToolPlan` 声称展示摘要可裁剪，但仍先以 4000 字上限校验 `summary`。模型返回有效 `kind` 和有界 `prompt`，仅摘要超过 4000 字时便被拒为 `AI_TOOL_PLAN_INVALID`。这只是可复现的代码缺口，不能据此断言它就是用户先前截图的真实供应商失败原因。

先补解析器及真实 `service.chat` 结算路径红测，再做最小修复：提示词/工具类型仍严格校验；展示摘要只做类型和控制字符检查、截为 240 字，不用无关的长摘要拦截有效方案。验证不调用付费服务商。

## 结果

先新增解析器图片/视频/PPT 及 `service.chat` 图片方案测试，4 个红测均命中 `parseToolPlan` 的 4000 字展示摘要上限。最小修复后，提示词长度与控制字符校验不变；展示摘要过长截为 240 字，不安全控制字符则回退为提示词简述。相同 `requestId` 重读不会再次请求服务商或重复扣除文本模型用量，工具本身不会被此解析步骤擅自执行。

验证：`npx vitest run server/ai/capabilities.test.ts server/ai/service.test.ts`（145/145）；`npm run typecheck`、`npm run typecheck:cloudflare` 均退出码 0。仅假服务商，没有真实图片/视频服务、旧 Windows 或用户截图对应请求证据；原 #2/#4/#32 仍保持进行中。
