# 工作包 34：V2 空会话创建与元数据 CAS

2026-09-24（Asia/Hong_Kong）。基线 `306b168`。仅改 AI 内部 V2 存储、测试与交接；未改“我的任务”“客户脉络图”、WorkBuddy、公开路由或客户端。

## 实际修改

- 内部 `conversation` 只允许单实体 `put`：创建时必须是空消息，新会话排在已有会话前；已有会话只能更改标题/时间标签，消息数组和项目归属逐字段保持不变。删除、跨项目搬迁、消息追加/改写和与其他实体混写仍拒绝。
- 预检时核验真实项目和既有对话内容，事务内重验准备 epoch、索引版本、会话 CAS、项目 revision、消息归属集合和账号最多 500 个会话；精确 mutation 回执可在后续改名后重放。保留旧 V1 记录作为迁移来源，测试中才人工激活 V2。
- 新建会话不得使用占位草稿键 `new-conversation`；旧 V1 若已存在这个 ID，仍可改标题，避免迁移时破坏旧数据。独立只读复核发现并促成该护栏。
- 按 [Cloudflare SQLite Durable Object 文档](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/) 核对同步 SQL 事务与抛错回滚边界：异步摘要/读取只作预检，真正写入及项目版本重验都在同步事务内，不在事务中等待网络或异步哈希。
