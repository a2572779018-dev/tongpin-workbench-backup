# 工作包 10：媒体缓存与认证身份稳定性

开工：2026-09-23 17:08（Asia/Hong_Kong）。映射原 33 项中的 #6、#16；仅处理 **同一应用进程内** 生成图片/视频切页后因认证对象更新而重复读取的根因，不声称跨进程永久缓存或已完成旧客户端验收。

## 根因与边界

`mediaCacheScope` 原以 `Session` 对象引用作 `WeakMap` 键。令牌刷新及资料更新都会创建新的 `Session` 对象，虽仍属同一登录，图片/视频组件却换了缓存范围并重新发 GET。直接改为 `user.id` 键会使同 ID 的新登录或不同租户共用私有媒体，不能这样修。

本包仅允许更动 AI 媒体缓存、鉴权中的 AI 缓存接续片段及对应测试；不触碰“我的任务”“客户脉络图”、WorkBuddy 独立手机预览、生产配置及发布。

## 已实施

- 新增 `transferMediaCacheScope(previous, next)`：只有调用方确认是同一登录链，且用户 ID、所有可见租户标识一致时，才把旧范围转移到新 `Session` 对象。不同账号、不同或含糊的租户标识均拒绝。
- AuthContext 只在已认证令牌刷新、当前会话资料更新时显式要求接续；新登录即使同 ID、退出登录、启动恢复后的 `/me` 均清空私有缓存，避免上一登录的 Blob/Object URL 沿用。
- 红测先行：新增“同登录刷新保留暖媒体”“账号/租户变动拒绝”“同 ID 新登录仍隔离”等测试，初次 3 项失败；实现后 `mediaCache.test.ts` 11/11、与视频聊天/客户脉络图集成合计 49/49 通过。

## 验证状态与未完成项

- 初次类型检查遇到并行代码块工作包未完成的源码；待其收敛后复跑 `npm run typecheck` 和 `npm run typecheck:cloudflare` 均通过（2026-09-23 17:12，Asia/Hong_Kong）。这是当前源码的类型证据，不等同于完整产品验收。
- 仍需在当前源码浏览器真实 UI 验证：A 视频或图片已显示 → 同账户令牌刷新 → 离开 AI 再回来 → 不重复 GET；随后重新登录同 ID 或另一个账号 → 旧 Blob/Object URL 不可复用。现有自动化覆盖缓存策略，但未完成该浏览器路径。
- `MediaTaskReply` 的任务状态仍会在 remount 后 GET 原 requestId；本包没有消除这一状态读取或瞬时占位。因此原 #6/#16 只能记部分修复，不能把“所有媒体切页零重载”标为完成。
- Cloudflare `toPublicUser` 当前不把服务端 `tenant_id` 发给前端。若管理员在同一登录链中动态迁移租户，客户端无法感知租户变化，缓存不能保证立即失效；这是多租户隔离的未完成验收项，不能宣称完全隔离。重新登录仍会清空。
- 仅本地缓存命中，不涉及服务商费用，也没有触发真实生成/下载/部署。
