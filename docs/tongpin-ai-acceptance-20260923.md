## 新发现的发布阻断

旧版 Windows 0.1.46 的普通登录、额度、聊天和工作区接口在本地合约测试未见确定字段级阻断；工作区保存回显的兼容缺陷已由 `f5402b7` 修复。但旧版图片/视频/PPT 请求不携带当前服务端要求的方案 ID、会话/素材绑定和审批信息，直接更新共享后端会被安全拒绝。不能通过服务端暗中补造授权来“兼容”。旧版只发送 quick/deep 档位，生产配置还须保留这两档可用。正式发布前必须确定旧 Windows 的迁移时序并做其二进制实机验证。

用户已指定优先评估官方 Dify Cloud API，同频 Cloudflare 后端不替换，也不在 Mac 装 Docker。Dify Cloud 提供长期可达的 HTTPS API；目前仍缺 Dify Cloud 账号/工作区、正式应用、插件、服务端密钥和真实多步验收。一个 Dify App Key 可通过稳定 API `user` 值服务多个终端成员；不能仅因同频有多个成员就断言触发自托管 Dify 的多工作区商业许可。自托管源码许可证与[官方云服务条款](https://www.dify.ai/legal/terms-of-service)应分开核对；单工作区不自动隔离不同组织的模型/工具配置。Dify 适配器还缺持久引擎选择、远端 ID、父子账本核验及断流核对，不应半接线或宣称策略已启用。
